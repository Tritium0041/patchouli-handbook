# Specification Changes

Category: Team Management & Workflow

## Summary
Avoid unnecessary spec changes. When needed, weigh pros and cons quickly. Communicate impacts to team.

## Use When
- Considering altering a feature after implementation started.

## Do This
1. List effort to change vs. benefit. If minor change but impact large, reconsider. If fundamental flaw, change is must.

## Checklist
- Is change improving player experience or just preference?
- How much existing work invalidated?
- Can phase the change?

## Anti-Patterns
- Changing specs daily
- Refusing necessary changes due to sunk cost
- Making changes without consulting affected team
